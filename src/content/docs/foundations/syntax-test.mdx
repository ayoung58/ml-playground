## 1. Headings, bold and italic

Use `##` for a section and `###` for a subsection. The page title is the only `#` heading, and Starlight adds it from the frontmatter. The headings of this very page are live examples of `##`.

```mdx
### A subsection

Plain text with **bold** for key terms and *italic* for emphasis.
```

## 4. Math

Inline math goes between single dollar signs. Block math goes between double dollar signs on their own lines.

```mdx
The model predicts $\hat{y} = \arg\max_k \, p(k \mid x)$ for each input.

$$
H(p) = -\sum_{k=1}^{K} p_k \log p_k
$$
```

The model predicts $\hat{y} = \arg\max_k \, p(k \mid x)$ for each input.

$$
H(p) = -\sum_{k=1}^{K} p_k \log p_k
$$

:::note[Two gotchas]
To write a literal dollar sign, escape it as `\$`, for example costs of \$5 per unit. Curly braces in plain text must go inside code fences or backticks, because MDX treats a bare `{` as the start of a JavaScript expression.
:::

## 5. Python code with a title and a highlighted line

Add `title="..."` after the language, and put line numbers in curly braces to highlight them.

````mdx
```python title="knn.py" {6}
import numpy as np

def knn_predict(X_train, y_train, x, k=3):
    dists = np.linalg.norm(X_train - x, axis=1)
    nearest = np.argsort(dists)[:k]
    votes = np.bincount(y_train[nearest])
    return int(np.argmax(votes))
```
````

````mdx
```ts title="distance.ts"

  let sum = 0;
````

## 7. Embedding a component

Import the component at the top of the page, then use it with a `client:` directive.

````mdx
import ScatterDemo from '../../../components/ScatterDemo';

<ScatterDemo client:visible />
````

<ScatterDemo client:visible />

:::note[Interactive components need a client directive]
Without a `client:` directive, Astro renders a React component to static HTML and ships no JavaScript, so sliders and buttons do nothing. Use `client:visible` to load the component when it scrolls into view, or `client:load` to load it immediately.
:::

## 8. Page template

Every concept page follows the same nine steps, in this order:

1. **Hook**: a question or surprising fact that makes the reader curious.
2. **Intuition widget**: a small interactive demo to play with before any formulas.
3. **The idea in words plus the formal version**: plain explanation first, then the math.
4. **Hyperparameters lab**: sliders and controls to see how each setting changes the result.
5. **Compare**: put the method side by side with a related one.
6. **Pitfalls**: common mistakes and failure modes.
7. **Check yourself**: a few questions with answers.
8. **Code**: a short, runnable snippet.
9. **Cheat sheet box**: a boxed summary of the key points to remember.
